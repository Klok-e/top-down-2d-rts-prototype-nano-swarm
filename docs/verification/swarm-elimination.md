# Swarm Elimination verification

ADR-0020 replaces Production Collapse with a count of surviving Nanobots and completed structures. The detector runs in `FixedLast` after Nanobot death cleanup and its deferred despawns, evaluates both sides together, and latches Victory, Defeat, or Draw. Sandbox bypasses outcome detection. Agent protocol v3 exposes `player_eliminated`, `opponent_eliminated`, and per-swarm `eliminated`, with no collapse aliases.

`tests/behavior/swarm_elimination.rs` covers stranded Defenders, each Nanobot type, each completed structure kind and ownership, excluded plans and owned deposits, final cleanup timing, births/removals, and permanent results. `tests/behavior/scenario_selection.rs` compares an eliminated player in Standard and Sandbox. `tests/behavior/agent_match_snapshot.rs` checks Draw and elimination fields through the public agent-control channel. Existing control tests cover terminal action rejection for all three outcomes.

`tests/playtest/opponent_gameplay_loop.rs::scripted_counter_assault_can_eliminate_opponent` drives the shared opponent/combat simulation to an actual Victory, checks that no opposing Nanobots or completed structures remain, and checks the banner text. `mutual_final_combat_deaths_show_draw_in_the_same_tick` uses real combat damage and cleanup to eliminate both final Defenders and display Draw in one tick. `tests/playtest/scenario_menu.rs::completed_match_still_allows_menu_selection_and_quit_through_agent_buttons` exercises the menu after Draw.

The obsolete recovery-state suite and its reachability-based defeat test were removed with the recovery checker. The independent occupied-cell Sink placement contract survives in `tests/behavior/sink_placement.rs::occupied_facility_build_cell_can_plan_its_local_sink`. Mapping-only banner coverage was replaced with actual text/visibility assertions; permanent-result protection lives at the simulation seam.

Behavioral failure evidence: the original checker returned Defeat for surviving stranded Defenders; the original Victory banner used collapse wording. Temporary production faults caused failures for early outcome evaluation, an unlatched result, disabled Sink placement, incorrect Draw serialization, and missing Draw input rejection. Draw serialization failed identically before and after moving the snapshot test to the public integration seam. All faults were restored before final verification.

The real `--headless --agent-socket` process returned protocol v3, advanced fixed ticks, and exposed an in-progress match with both elimination flags false. Its captured 1280×720 view showed the textured map, readable HUD and intent buttons, surviving Nanobots and structures, and no terminal banner. Client shutdown exited successfully, removed the socket, and released the lifecycle lock. The session used private runtime and configuration directories; retained evidence is under `target/swarm-elimination/`.

The three offscreen outcome banners show centered, unclipped text with green Victory, red Defeat, and gold Draw styling. The full screenshot suite uses a temporary ALSA null device to avoid a host JACK initialization stall. A direct-binary retry omitted Cargo's asset-root environment and was discarded after missing-asset visual failures; the final screenshot verification runs through Cargo with the normal assets.

Final checks passed: `cargo fmt`, `cargo clippy --all-targets -- -D warnings`, `cargo test` (344 unit, 491 behavior, and 64 playtests passed; two existing ignored playtests), and `cargo test --test screenshots -- --ignored` with the temporary null audio device (44 passed). Fresh assault/Victory, fill-indicator, logistics, and three Defender combat captures were inspected: fonts, textures, and sprites loaded; the Victory text was readable and centered; ongoing simulation views had no obstructing outcome banner. Standards and Spec reviews finished with no findings after the snapshot-test relocation.
